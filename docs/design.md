# flowdeck: design

Date: 2026-10-24. Status: awaiting approval.

## Intent
One personal Claude Code mod that replaces three installed ones: **savvy-flow** (orchestrated delivery skill + 5 worker agents), **savvy-progress** (progress bar above the prompt, side panel of agents, `progress` and `step` tools) and **context-bar** (context-window breakdown). The owner wants a single set of their own, with their own command names, and the context view living inside the agents side panel instead of a separate bar above the prompt.

## Goals
- `/flowdeck <task>` starts the orchestrated flow (what `/savvy-flow <task>` does today): the session model plans and reviews, tiered worker subagents implement. The skill is renamed `flowdeck`.
- `/flowdeck` with no task takes over the work already underway in the session (the owner's current set of tasks): the orchestrator reads the conversation and the session's open task list, builds the plan from them and shows them as the flow in the panel, so running tasks appear under the flowdeck panel. Once `/flowdeck` has run, the flow stays linked for the rest of the session: every task that appears later (new requests, items the model adds to the session's task list) is added to the same flow and the panel, and none is dropped. This linking is the only new behaviour beyond a rename.
- `/flowdeck-agents` shows or hides the side panel (replaces `/agents-info`). The side panel is titled `flowdeck`.
- Progress bar above the prompt stays as savvy-progress draws it, including the crew-size button that opens the panel.
- The side panel gets a **context section** at the top: stacked bar by category, legend with tokens and shares, and the auto-compaction point. Desktop draws it as SVG, the terminal as text. It refreshes after each turn and after `/compact`.
- A **context button inside the panel**, next to the compact/expand button, shows or hides that section. The choice is remembered across sessions.
- The agents list, planned tasks, cost/tokens/time summary, the `progress` and `step` tools and the five tiers behave exactly as in savvy-progress/savvy-flow 1.2.0.

## Non-goals
- No context bar above the prompt, and no `/context-bar` command.
- No other new features in this first version beyond adopting running tasks.
- Not published; personal use only.

## Anti-goals (failure even if it works)
- Clashing with Claude Code's built-in `/context` command.
- Running together with the originals: duplicate tools and pane ids. The three originals are disabled before flowdeck is enabled.
- Any change that leaves `ANTHROPIC_BASE_URL` set or blocks Remote Control.

## Constraints
- Lives in `server-setup/claude-mods/flowdeck/`, registered in that marketplace (`paavu-mods`), same layout as the other mods there.
- Built from the sources in `~/.claude/plugins/cache/claude-kit/{savvy-flow,savvy-progress}/1.2.0` (MIT, johnnyvizz) and `claude-code-mods/context-bar/0.1.2` (hamzafer, MIT, checked 2026-10-24; keep both copyright notices in a LICENSE/NOTICE file).
- Context data comes from `$.session.usage({breakdown:'summary'})`, as context-bar does.

## Decided by the owner
- Name `flowdeck`; commands exactly `/flowdeck` (with a task: starts a flow; with no task: adopts the tasks already running in the session into the flowdeck panel) and `/flowdeck-agents` (toggles the panel).
- Context toggle is a button inside the side panel only.
- Old context bar is dropped once flowdeck works.

## Left to the builder
- Internal naming of tools and the pane id (suggested: tools `mcp__flowdeck__progress` / `mcp__flowdeck__step`, pane `flowdeck-agents`), plus the matching edits in the skill and agent files that call them.
- Agent names: keep `savvy-*` or rename to `flowdeck-*` (suggested: rename for consistency, since both sets cannot coexist anyway).
- Exact SVG look of the context section, matching the existing panel styling.
- Tests (reuse context-bar's pure-function tests for token and bar maths).
- Whether the context section is open or hidden by default (suggested: shown).

## Rollout
Build, run the mod tests, disable savvy-flow, savvy-progress and context-bar, enable flowdeck in a new session, check the panel and the button, then uninstall the three originals and log it in the mod ledger.

## Builder-check answers (builder's calls, 2026-10-24)
- Licence: context-bar is MIT; copying its logic is fine, keep attribution.
- Persistence: use the mod store (`$.store.get/set`), as context-bar does; global, key `contextShown`. Never share keys with the originals.
- Refresh: `turn.complete` plus `session.compact` events; data from `$.session.usage({breakdown:'summary'})`, which carries categories, `rawMaxTokens`, `autoCompactThreshold` and `isAutoCompactEnabled` (see context-bar's `toReading`).
- Rendering: both paths required, as savvy-progress already splits `e.surface === 'desktop'` (SVG) from terminal (text rows). Verify both at rollout.
- Outside references to old names: only the `enabledPlugins` entries in `~/.claude/settings.json` (savvy-progress, savvy-flow, context-bar). Replace them with flowdeck at rollout.

## Additions after the first version
- Usage: the five-hour and weekly limits with reset times, a draining bar, an even-pace mark and a burn forecast (recent ~30 min pace and window average); store key `usageShown`.
- 24-hour times and the reset switch, 1.0.0018: every time of day goes through `hhmm` in hooks/time.ts (24-hour `HH:MM`, no AM/PM); each Usage window's label, reset line and a `◷` Button (`usage-reset-session`/`usage-reset-week`) sit in a native row above the drawing (`usageSvg(..., { header: false })`), and the one switch between the time left (default) and the exact time is global, engine-store key `usageRemaining`.
- Archive (formerly History): the last 50 flows across projects, newest first, saved on finish, on replacement and as open at session end; store key `history`, toggle `historyShown`, off by default.
- Plans (ported from plan-progress): the plan model in `hooks/plan.ts` (stages or `kind: "todo"`, short ops, at most 3 plans); the main-session tool `mcp__flowdeck__plan`; the Plans panel section with `Clear finished`; up to 2 open plan rows in the band. Saved per session under store key `plans`, last 20 sessions. A `prompt.compose` section `flowdeck:plan-rule` tells the model when and how to plan; no gate, no sounds, no Stop block, no nudges.
- Agent state colours and tool word: each agent row names its state (`Running · <tool>` blue-violet, `Needs approval` amber, `Done` green, `Error` red), the same colours as the plan states.
- Band layout: the flow row first, then the open plan rows, then whatever other mods draw; the row shrinks and clips instead of pushing neighbours; ✕ hides the band only, the Band button or a new flow brings it back.
- Load order: mods nest in the order of `enabledPlugins`, first outermost; flowdeck must come before next-steps, or next-steps squeezes the band.
- Child items per agent: done; a worker's `step` list shows as foldable items on its agent row.
- Per-project saved data: the archive and plans moved from the shared store to `<project>/.claude/flowdeck/history.json` (every flow, never cut: past 2,500,000 bytes the oldest move to archive volumes `history-<n>.json`) and `plans.json` (every session, none dropped), with a `*` `.gitignore` in that folder; each save re-reads the files, merges and writes them whole, so two projects never overwrite each other.
- Store fallback: with no working folder or a failed write, that save goes to the store keys `history`/`plans` as before; this project's entries in the store key `history` are merged into the latest view and back into `history.json` with the next save (the store itself is never changed by that); plans are not migrated.
- Data safety (1.0.0007): sizes are UTF-8 bytes; no write over 3,900,000 bytes is sent; a file that cannot be read, or whose existence stat, the listing and `exists` cannot tell, is never written over; every save writes the flow's own side file `history-extra-<startedAt>.json` first, and a load reads back every side file whose flow neither `history.json` (as finished) nor a volume holds, so two sessions saving at once can duplicate or delay a flow, never lose it.
- Archive (formerly History), 1.0.0008: the panel section, its button and keys (`archive`, `archive-more`, `archive-older`, `archive-seg-<file>`, `archive-latest`, `archive-<id>-…`) and the code say Archive; the old archive segments are archive volumes (`Older volumes (k files)`), indexed by the volume index. Saved data keeps its names, so nothing moves: `history.json`, `history-<n>.json`, `history-index.json` (its JSON field `segments`), `history-extra-*.json`, the store keys `history` and `historyShown`; `FLOWDECK_HISTORY_SEGMENT_MAX` still works beside the new `FLOWDECK_ARCHIVE_VOLUME_MAX`. The code moved out of `hooks/register.tsx`: `hooks/archive.ts` (pure), `hooks/archive-store.ts` (files and store, through an `Io` built in register.tsx, since `$` may not cross an import) and `hooks/archive-view.tsx` (the section and its groups).
- Archive finished items, 1.0.0009: an `Archive` button (`archive-item-<agent id>`) on each finished row of the open flow archives it and every older un-archived finished row (`AgentRun.archived`); the flow's entry is upserted at once with only those rows and `partial: true`, and the flow's next full save replaces it by id; totals still count archived rows, and rows are hidden only once the entry was kept.
- Archive groups flat, 1.0.0010: an open group draws its rows flat, newest first (`flowView` with `flat: true`, no `Finished · N` fold; the live panel keeps it); the first group shown is open by default, and a press is kept in the session-only `Panel.openEntries`/`closedEntries` until a volume switch or `Back to latest` clears both.
- Archive group line, 1.0.0013: the fold button is one line, `groupLine` in hooks/archive.ts (end date and time, then `N items`: the entry's runs, or its tasks without runs; ` · running` when partial), dropping the time and then the word `items` when narrow; no title, `done/total` or status line in the group (`entryLine` removed; `formatEntry` and the saved fields unchanged).
- Archive icon, 1.0.0011: the row's `Archive` text button became a plain dim one-glyph Button (`⤓`, same key `archive-item-<agent id>`, Button has no tooltip prop); the desktop row keeps one 28 px column on the right (the icon on top, the chevron below), the terminal puts the icon right after the task name.
- Calmer redraws and path-free keys, 1.0.0014: the running clocks tick every `TICK_MS` = 5 s (was 1 s; each redraw gives the desktop buttons new handles and a click on an old one is refused), and keys built from an archive entry id or a plan id use `keyOf(id)` from hooks/archive.ts (`k` + FNV-1a 32-bit in base 36 + the length, only `[a-z0-9]`), e.g. `archive-<keyOf(id)>`; fold state keeps the real ids.
- The panel always draws, 1.0.0016: every held value is read through its normalizer in hooks/shapes.ts (a reload keeps what an older version wrote; a `panel` first written before `openEntries` existed threw at archive-view's `p.openEntries.includes` once two Archive groups showed, and the pane stayed blank); Context, Usage, Plans, the Archive and each of its groups, the flow block and each agent row draw in their own guard (`<label> could not be drawn`), the Pane hook's `.catch` draws the top buttons and `flowdeck could not draw this panel`, the band's `.catch` gives way to what is drawn below it; the Archive is shown by default (a stored `historyShown` still wins); Plans and the flow block take no place without plans, a flow or a run.
- Finished plans in the Archive, 1.0.0017: every place a plan becomes done (the plan tool, the main turn's auto-close, which also closes plan-mode plans) calls `archivePlan` in register.tsx, which saves `planEntry(plan)` (hooks/archive.ts: id `plan-<plan id>-<startedAt>-<project>`, `plan` holds the finished plan, no tasks or runs, dated by `endedAt`) through `saveArchive` like a flow, after the archive saves under way; `addEntry` places a plan entry by its end; the group's fold line counts steps and, opened, draws the plan with the Plans section's drawing (`planDrawing`); `Clear finished` archives any done plan not saved yet and removes only those the archive kept; Archive groups no longer draw a flow's planned tasks.
- Archive icon after the task name, 1.0.0015: every desktop agent row (live panel and Archive groups) is a column: line 1 is a native row (a 42 px empty `Svg` indent, the task name as bold `Text wrap="truncate-end"` in a shrinking Box, the icon, a `flexGrow` spacer, the chevron at the far end; icon and chevron in `flexShrink={0}` Boxes), then `agentSvg(W, a, at, { titleOutside: true })` at the full width, 48 px tall, without its title line; planned rows and the terminal row are unchanged.
- Incomplete runs, 1.0.0019: a run that ended OK (`status: 'done'`) with a step list not all done (`stepDone < stepTotal`) is `Incomplete`, amber (`STATE_COLOR.needs_input`): the bar at `stepDone/stepTotal`, an amber half-ring mark (terminal `◐`), no `archive-item-<id>` icon, and an archive press on a newer row passes over it (it stays in the live list; it is still listed and counted in `Finished · N`). Done, the tick and the full green bar need no step list or every step done. One set of helpers in hooks/agent-state.ts (`isIncomplete`, `isComplete`, `isSettled`, `markOf`, `progressOf`) drives the state word, the bar, the mark, the terminal glyph and archive eligibility; the flag is derived from the saved `status`/`stepDone`/`stepTotal`, so old saved runs and held values need no new field. The flow's own done count (the accepted count from `progress`) is unchanged.
- Task numbers and waits, 1.0.0020: hooks/tasks.ts holds the task side (`norm`, `cleanAfter`, `linkRuns`, `taskOf`, `unstarted`); a run belongs to the task whose title is its description (as before), its row leads with the task number and its meta line carries `after N, M` after the effort, dropped first when the stats would lose room (desktop and terminal, live and Archive groups, from `entry.tasks`); planned rows add `ready` (blue-violet, `STATE_COLOR.running`) when every waited-for task has a complete run (or the session task list completed it), and independent planned tasks read `ready` too; `progress` cleans `after` (whole numbers of existing tasks, not itself, no cycle) and takes it in `add` too; the tool doc and SKILL.md tell the orchestrator to pass `after` and launch every ready task in parallel.
- Task linking and a self-contained repo, 1.0.0021: `linkRuns` in hooks/tasks.ts links runs to tasks at draw time, runs in start order: (1) exact title (the first rule, as before); (2) a leading `#3`/`[3]`/`task 3` in the description, else the description without it as a title; rules 1-2 may give a task several runs (return rounds); (3) `titleScore` ≥ `MATCH_SCORE` 0.6 (whole-word containment of at least 4 letters, or the shared share of the shorter title's words, short and stop words left out) among tasks no run has, tie to the worker's tier, a remaining tie links nothing; (4) a flowdeck worker takes the only task of its tier that no run started at or before it had (mirrored and session-completed tasks excluded). Rules 3-4 are one to one. The link drives the row number, `after`, `unstarted` (planned list) and the done test for `ready`; nothing new is saved, so archive groups and old data link the same way. `workerTier` is the one tier parser (`isWorker`/`tierOf` use it). The Agent prompt is not read (the spawn event gives only the description). The repo is its own marketplace (`.claude-plugin/marketplace.json`, `flowdeck-mod`, source `./`), README documents install/update/rollback from a clone, CHANGELOG.md, tag `v1.0.0021`.
- Accepted tasks and worker closure, 1.0.0022: `Flow.accepted` and `ArchiveEntry.accepted` (optional task numbers, normalised in shapes.ts/archive.ts, so held atoms and saved entries from before load) record which tasks the orchestrator accepted; `progress` `done` takes an array of task numbers (added to those accepted before, the count is the set's size) or the old integer (count only, the list kept). `acceptedOf` in hooks/tasks.ts reads the list, or the first `done` tasks when there is none. Accepted tasks leave the planned list and count as done for `ready`; `acceptedOnly` gives the accepted tasks no run belongs to, drawn as `Accepted · no worker run` rows (green tick, no bar, no archive icon) at the end of the Finished list and in Archive groups, counted in `Finished · N`; an accepted task's Incomplete run reads `Incomplete · accepted` (`headOf`), never Done. The five worker files and SKILL.md make closing the step list the worker's duty and an Incomplete return a review defect; the mod never overrides Incomplete.
- Band faults said, 1.0.0023: the AbovePrompt hook's `.catch` (a throw, a timeout, or a tree the surface refused after the hook returned) calls `noteBandFault` in register.tsx: once per reason per load (`bandFaults`, cleared at session.start) it writes `$.ui.log` (transcript, debug log too) and, from a `$.clock.after(1)` timer since a drawing may not write held values, the held `bandError` (contract key `bandError`), which only the Pane reads and draws as a dim `band error: <reason>` line under the top buttons; session.start clears it. `next(e)` failing beneath the band leaves `theirs` null, the flow row still drawn. The band never reads `bandError`, so a failing band cannot redraw itself in a loop. Load order: a mod before flowdeck in `enabledPlugins` that answers AbovePrompt without `next(e)` (replay-theater with a replay waiting) means flowdeck's hook never runs; only the order fixes that.
- Tabs, 1.0.0024: below the Context and Usage toggles (and the `band error` line, Context and Usage), the Pane draws one group (`flowdeck-group`): `tabRow` in register.tsx (Buttons `tab-active`, `tab-finished`, `tab-plans`, `tab-archive`, then a spacer and the dim `band` Button; the selected tab is a Button holding a bold, underlined `Text` in `ACCENT` and its press does nothing, the others are dim labelled Buttons that set `Panel.tab`), then only the selected list, in its own `safe` guard (`<Tab> could not be drawn`). `Panel.tab` (`'active'|'finished'|'plans'|'archive'`, default `active`, session-only) and `Panel.archiveLatestCount` are normalised in shapes.ts (an older held panel, or a tab of the wrong kind, reads as `active`); `isDoneCollapsed` is gone, `isPlansShown`/`isArchiveShown` are still filled from their store keys but nothing reads them. `FlowView.rows` (`active`, `finished`, `all` for an Archive group) replaces `flat` and the Finished fold; `rowsOf` (running, finished not archived, archived count, accepted rows without a run) feeds both the lists and `flowCounts`, so a count is always the rows its list draws; the Archive count is `archiveTotal` in archive-view.tsx (the latest part's entries, or `archiveLatestCount` while a volume is shown, kept by `openVolume` and by saves made while browsing, plus every volume's index `count`). `groupLine` gives `<entryDate> (N)` with ` · running` for a partial entry, then the date without the time. The desktop compact strip stays above the top buttons on every tab; Active and Finished show the compact block in compact mode. Tests select a tab with a press (`tests/tabs.ts`).
- Session files, index, trash, completion order, 1.0.0025: the archive is `archive/<keyOf(id)>-<startedAt>.json` per session (the whole ArchiveEntry) and `archive-index.json` (`{version: 1, sessions: ArchiveRecord[]}`, hooks/archive-index.ts: `recordOf`, `parseIndexFile`, `upsertArchive`/`upsertTrash`, `reconcile`, `byNewest`); hooks/archive-store.ts: `saveSession` (file first via `putSession`, never over another session, an unreadable file or a newer copy; then `heal` + upsert + `writeIndex`), `heal` (orphans read once and added, missing files marked, an unreadable index never written, a damaged one rebuilt only after a whole scan, kept first in `.trash/damaged/`), `loadArchive` (heal, `migrate` the `history*.json` files once per file into session files with `archive-migrated.json`, `importStore` of this project's store entries, heal the trash, `reconcile`), `trashSession` (copy to `.trash/<file>-t<ms>.json`, trash record, archive record `trashedAt`) and `restoreSession` (file back if needed, archive `restoredAt`, trash `restoredAt`); the engine's fs has no move or remove, so the session's file stays in `archive/`, and the list a session shows in is its latest event across both indexes (end, `trashedAt`, `restoredAt`), which makes every crash point and two-session race resolve the same way. Index guard 2,500,000 bytes (said, never dropping records), session and write guard 3,900,000. Held atoms `archiveLists` (`{records, trash, warnings}`) and `archiveDetails` (at most `DETAILS_MAX` 10 files for open groups; one more folds the oldest-opened) replace `archive`/`volumes`; `Panel` drops the volume fields and adds `trashLimit`, `confirm` (`{list, id}`, one open) and the `trash` tab; `ARCHIVE_PAGE` 50. hooks/archive-view.tsx draws a session row per record (fold `archive-<k>`/`trash-<k>` with `foldGlyph` first, `archive-del-<k>` ✕ or `trash-restore-<k>`, the dim `summaryLine`), the body from `archiveDetails`, and the inline `confirmBlock` (`archive-trash-<k>`/`archive-cancel-<k>`, `trash-restore-yes-<k>`/`trash-cancel-<k>`). hooks/order.ts `newestFirst` (end desc, start desc, id) orders every list; hooks/time.ts `doneText` prints a completion time (`HH:MM` today, `Oct 29 · HH:MM`); `Flow.acceptedAt`/`ArchiveEntry.acceptedAt` (task number → ms, set by `progress` and the session-list mirror) date accepted rows, an archive entry's end standing in for old data; `archivable` and so the ⤓ sweep use the same order. hooks/fold.ts `foldGlyph`: every fold chevron is the first element before the name (desktop agent rows: a 24 px indent then an 18 px chevron slot, so names line up at x 42; terminal: `▣ ▸ name`, `▣   name`, `▢   3. title`, `✓   3. title`). The env limits `FLOWDECK_ARCHIVE_VOLUME_MAX`/`FLOWDECK_HISTORY_SEGMENT_MAX` are gone.
- Row-based band, folds on every agent row, step times, 1.0.0026: `flowProgress(f, list)` in register.tsx (on `rowsOf`) is the one source of the tab counts (`flowCounts`) and the band (`shownFlow` puts its `done`/`total`/`running` into the Flow that `label`, `ratio`, `rowSvg` and `barText` draw, desktop and terminal): active = running runs + queued tasks, finished = finished runs not archived + Accepted rows, done = complete finished runs (archived ones too) + Accepted rows, total = active + finished + archived runs; a flow without rows keeps `Flow.total`/`done`. The `progress` tool's `ok: <label>` still reads the orchestrator's numbers. The band's flow row takes the terminal text path when `e.surface === 'terminal'` (the terminal kit has an Svg that draws an empty box). Every agent row's fold Button (`agent-fold-<id>`, same keys and `openAgents` state) sits in the chevron slot, `dimColor` when the run has no items; an opened row without items draws `detailLines` (model · effort, `started` + `doneText`, tokens, cost) and `No steps reported yet` as dim ITEM_H rows (`noteSvg` at the items' title column x 58; terminal: dim indented Text; keys `agent-detail-<id>-<i>`). hooks/agent-items.ts: `stamp` sets `doneAt` only when unset (next, done, active's earlier items, failed, finishItems, a resent done/error list item, which keeps the old `startedAt`); `timedItems(items, run)` fills the drawn times (start: nearest earlier ended item with an end not after its own, else the run start; end: the next item's start, else the run end, else its start), used for every drawn item list, live and in Archive groups; nothing new is saved.
